## 1. 본인 저장소 만들기

교수자 템플릿 https://github.com/lec-algorithm/algorithm-env 에서 `Use this template > Create a new repository`로 본인 저장소를 만듭니다.
예를 들어 저장소 이름을 `sorting-comparison`으로 정할 수 있습니다. 실제 계정명과 저장소명은 본인이 정합니다.
저장소 공개 여부는 수업의 안내를 따르되 교수자가 코드에 접근할 수 있어야 합니다. 보고서에는 이름과 학번이 들어 있으므로 공개 범위도 확인하세요.

## 2. 압축을 풀고 파일 넣기

다운로드한 업로드용 ZIP을 압축 해제합니다. 그 안의 `sorting-comparison` 폴더 **내용물**이 저장소의 최상위에 오도록 넣습니다.
`Makefile`, `src`, `tests`, `tools`, `results`, `report`, 안내문이 같은 최상위에 있어야 합니다.
ZIP 파일 자체를 저장소에 한 개의 파일로 올리는 방식은 피하세요.

템플릿의 기존 `src`, `tests`, `Makefile` 예제는 교체하고 기존 `.devcontainer`, `Dockerfile`, `compose.yml`은 유지합니다.
Codespaces를 쓰는 경우 저장소의 `Code > Codespaces`에서 연 다음 파일을 넣고, 터미널에서 `make test`와 `make run`을 실행합니다.
작업을 마친 뒤 파일 변경 사항을 커밋하고 원격 저장소에 반영합니다. GitHub 저장소 화면에서 파일들이 보이는지 확인하세요.

## 3. PDF에 저장소 URL 입력

GitHub에서 **본인의 저장소 첫 화면 주소**를 복사합니다. 샘플 저장소나 Codespace 주소가 아닙니다.
주소 형식은 `https://github.com/본인계정/본인저장소`입니다. 이 예시 문자열을 그대로 쓰지 마세요.

`report/REPORT.pdf` 첫 페이지의 `GITHUB_REPOSITORY_URL`은 입력 가능한 PDF 필드입니다.
필드를 클릭하여 전체 선택 후 실제 주소를 붙여넣고 **다른 이름으로 저장**합니다.
다시 열어 주소가 보이는지, 잘리지 않는지 확인합니다. 뷰어가 입력·저장을 지원하지 않으면 수정용 `REPORT.docx`에서 같은 문자열을 실제 주소로 교체한 뒤 PDF로 내보내세요.
필요하면 PDF로 인쇄하여 주소를 본문에 고정하되, 인쇄 후 8페이지와 글자·그림 상태가 유지되는지 확인합니다.

제출에 사용할 최종 PDF와 저장소의 `report/REPORT.pdf`를 일치시키고 DOCX/Markdown에도 같은 URL을 기재합니다.
보고서 수치를 재측정 결과로 바꾸었다면 해당 CSV·환경 정보와 보고서의 표·그래프·설명이 일치하는지 확인합니다.
